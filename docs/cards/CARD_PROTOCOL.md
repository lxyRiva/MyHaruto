# CARD_PROTOCOL — 卡片状态台账机制（v1 · 2026-09-11 用户定稿）

> 适用范围：docs/cards/ 全部卡文件（现有 4 张 + 未来所有卡）。
> 违反任何一条 = 流程事故，规划层主责。

## 1. 状态标记必附证据
每张卡文件头部维护状态行，格式：

【状态】· 时间 · commit=hash/tag · 证据=报告路径

- 无证据 = 视为未完成
- hash = 该卡对应工作的 commit（或 stash/tag 引用）
- 证据路径 = 交付报告/截图/录屏在 docs/evidence/ 下的相对路径

## 2. 权限分层
| 角色 | 卡文件权限 |
|---|---|
| 开发/测试 | 只读（禁改卡文件，含状态行） |
| 规划层 | 独写状态（唯一可更新状态行的角色） |

违反 = 流程事故。

## 3. 规划层核实 = 附实际命令输出
每次更新状态行时，必须在同一次操作中贴出以下命令的实际输出（写入
本文件或规划层工作日志），禁止只写"已核实"：

```
git log --oneline -3
git show --stat <hash>
```

## 4. 动态流程分级
每条子任务独立标级，前缀 [L0/L1/L2/L3]：

| 级 | 范围 | 流程链 |
|---|---|---|
| L0 | 文档/注释 | 规划→开发→规划复核 |
| L1 | 单文件小改 | 规划→开发→开发自测→规划复核 |
| L2 | 多文件/接口变更 | 规划→开发→测试→规划复核→用户手测 |
| L3 | 架构级/语义变更 | 规划→开发→测试→用户手测→commit→tag |

## 5. 用户审查兜底
规划层设计流程后返用户审查（只返新增项+流程设计，不返全量重复）。
用户 24 小时未审 → 默认按严格一级流程走。
禁止 zcode 自行"视为通过"。

## 6. 误标纠错机制
状态标错 → 立即回滚为"未完成"，标"⚠️ 误标·修正时间·轮次"。
累计误标 ≥3 次 → 重大失误，上报用户。

第一章 · 卡面结构（四段式，顺序不许调换）

【第一段：卡头（4 行，缺一不可）】
第 1 行：版本头 —— 【版本=vX.Y｜取代=vX.Z｜生效=是｜vX.Z 及更早作废】
第 2 行：本卡一句话 —— 【本卡=xxx（独立执行卡，非文件替换）】
第 3 行：改动一句话 —— 【改动=相对 vX.Z：xxx + xxx + xxx】
第 4 行：状态行 —— 【状态】整卡状态 · 日期 · commit=xxx · 证据=xxx

【第二段：当前有效指令】（开发只读这段，规划/审查都读）
每条任务一行状态行+指令正文。
每条任务状态行格式（严格照抄，不许简化）：
  Tn 【状态emoji】 状态词 · 日期 · commit=xxx/未提交 · 证据=路径
状态词只能从这 6 个里选：
  待开工 / 施工中 / 开发已完成 / 测试通过 / 手测通过 / 已完成
禁止自创状态词。禁止"差不多完成""基本OK"等模糊词。

【第三段：迭代日志】（规划/审查读，开发可跳过）
格式：每轮一行，从 v1.0 开始累积
  vX.Y → vX.Y+1 · 日期 · 改了什么 · 为什么改
禁止删除历史行。禁止合并同类行。

【第四段：冻结规则】
写清"什么条件下不许 commit / push / 开工"。

第二章 · 任务级状态更新规则（最核心）

【规则 2.1】状态粒度到"每条子任务"，不是整卡一个状态。
【规则 2.2】每条状态行必须带证据（4 类选一：截图/录屏路径、
  commit hash、测试报告路径、数据文件验证）。没证据=打回。
【规则 2.3】规划层核实状态必须贴 git 命令输出。没贴=不认。
【规则 2.4】状态升级逐级走，禁跳级。任何跨级升级=违规。
【规则 2.5】状态回退：标【⚠️ 误标·修正日期·误标轮次】，计入误标次数。
  累计 ≥3 次 → 用户有权直接裁定换规划 Agent。

第三章 · 迭代追加规则

【规则 3.1】同一张卡滚动迭代，不新开卡。只有任务性质变了才新开。
【规则 3.2】作废指令保留原文+标注作废+写明原因。
【规则 3.3】新指令必须说明"取代哪条旧指令"。
【规则 3.4】差异说明必须逐条列，禁"无其他范围变化"。
【规则 3.5】迭代轮次禁跳号。禁混"任务阶段版本"与"卡修订版本"。

第四章 · 长期未完成项处理

【规则 4.1】连续 3 轮未完成 → 卡头标【⚠️ 长期未完成】，
  规划层必须给 a)拆小 b)作废 两选项。不许无限期挂。
【规则 4.2】挂 3 轮不动=任务定义太大/障碍未解决/不需要这条。

第五章 · 卡面示例（照抄结构）

【示例：RF-B1-T1-T5.md v2.1】
---
【版本=v2.1｜取代=v2.0｜生效=是｜v2.0 及更早作废】
【本卡=RF-B1 收尾补测+T1 Toast+T5 追查（独立执行卡）】
【改动=相对 v2.0：T5 方向修正 + T3 双链边界补答 + T1 Context 定死】
【状态】施工中 · 2026-09-12 · commit=未提交 · 证据=docs/evidence/

T1 ✅ 开发已完成 · 2026-09-12 · 证据=31-t1.png
T2 ⏸ 未完成 · 原因：独立 I=2 分来源待查
T3 ✅ 开发已完成 · 证据=32/33.png
T4 ✅ 开发已完成 · 证据=json-verify-task11
T5 ⏸ 未完成 · 原因：backups 路径未确认

【新增 v2.1 禁止事项】
  禁止在未获用户明确授权前，对已有历史数据做删除或修改。

第六章 · 每轮迭代的 SOP（规划层操作步骤，7 步缺一不可）

第 1 步：读开发报告，逐条核对每条任务状态
第 2 步：跑 git log --oneline -3 / git show --stat，核实 commit 证据
第 3 步：更新卡文件对应任务的状态行（只改状态行，不动指令正文）
第 4 步：若本轮有新任务/修改方向，加在"当前有效指令"段末尾
第 5 步：写本轮迭代日志（vX.Y → vX.Y+1 · 日期 · 改了什么 · 为什么）
第 6 步：卡头版本号+改动行更新
第 7 步：git diff 展示改动，返用户审查

禁止行为：
  - 第 3 步不动指令正文——状态行和指令是两码事
  - 第 4 步直接删旧指令——作废要保留
  - 第 5 步省略迭代日志——日志是历史凭证
  - 跳过第 7 步——用户有权看到每次改动

第七章 · 规划层出卡提醒语句（每张执行卡必须嵌入，禁省略）
═══════════════════════════════

规划层出执行卡时，在卡头之后、正文之前，必须嵌入以下提醒块：

⚠️ 本卡提醒（逐条读，不可跳过）：
1. 本卡为第 N 轮迭代（或首版），先读 docs/cards/<路径>.md 上一版确认遗留
2. 施工前反问：全消费面清单（文件:行号）+逐点结论
3. 停手不 commit 不 add
4. 证据=每条截图/录屏+反例，禁纯文字
5. 工作区边界 §11
6. 冲突/卡漏→停手回报规划层

省略此块 = 规划层流程违规。

第八章 · 多轮迭代标注（同一任务卡第 N 轮开发）
═══════════════════════════════

同一张任务卡经历多轮开发时，每轮派发的执行卡**必须标注轮次**：

格式：卡标题首行加「以下是本任务第 N 轮开发」

示例：
  第一轮：「执行 RF-B1 收尾阶段 2 补交（首版）」
  第二轮：「以下是本任务第 2 轮开发。上一轮遗留：xxx」

**目的**：开发清楚知道这是同个任务下的第 N 轮，不是新任务。
**禁止**：不给轮次标注就让开发开工（开发会困惑是新任务还是续作）。

配套要求：
- 卡头版本号递增：vX.0→vX.1→vX.2（禁跳号）
- 每轮的【改动=】行逐条列相对上一版的变更
- 上一轮未完成项在正文开头列明（滚动遗留清单）
- 规划层在每轮批复中明确"本轮续作/本轮新任务"

第九章 · 规划层实时状态维护（铁律）
═══════════════════════════════

1. AGENT_STATE.md **每轮必刷**——开发交付/用户批复/规划层出卡后，
   立即同步，不等阶段收尾。
2. 卡文件状态行**每轮必刷**——Tn 状态变更立即更新对应卡文件。
3. 记忆追加**每轮必做**——关键裁定/事故/新规，禁攒批。
4. 写入工具统一 python utf-8——禁 bash heredoc 写中文（GBK 事故）。
5. 以上三条任一未做 = 规划层流程违规，计入误标次数。
